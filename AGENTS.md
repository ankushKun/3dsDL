# 3dsDL

A Nintendo 3DS homebrew app (C++17, libctru, citro2d) that downloads files, installs CIAs, manages files and titles, and receives files over Wi-Fi.

## Build and test

- `scripts/build.sh` builds the .3dsx and CIA in Docker (pinned devkitARM image) into `dist/`. `THREEDSDL_BUILD_JOBS=6` speeds it up. It cleans first, so never run two builds at once.
- `make -C tests check` runs the host tests (portable code in `source/core` and `source/net`). Keep new logic there, with tests, when it does not need the console. TMPDIR must ignore case, as FAT does: macOS's does, and on Linux CI mounts an ext4 casefold folder.
- `VERSION` holds the version; releases are a tag push, and CI publishes them.

## Layout

- `source/app`: screens and console glue. `ui.hpp` is the whole drawing toolkit; read it before drawing anything.
- `source/core`, `source/net`: portable logic, host-tested.
- `romfs/ui/icons.png` and `source/app/icon_atlas.hpp` are generated by `scripts/make-ui-icons.py` (needs Chrome).
- `resources/banner/`: the 3D HOME Menu banner, built as code by `model.py`, which refuses framings that clip.
- `romfs/web/editor.js.gz` is the page's code editor (CodeMirror), built by `scripts/make-editor.sh` from `resources/editor/` (needs Node; versions pinned in its lockfile). The build is reproducible, so rebuilding without a change leaves the file as it was.

## UI rules

`docs/DESIGN.md` is the spec. In short:

- Facts, not explanations (rule 7): no taglines, help paragraphs or footnotes. Show values with `ui::drawFacts` (or `ui::drawEmblem` when the top screen has nothing to add), and fix a label or layout rather than add a sentence.
- Text never overflows: `drawMarquee`, list rows and tabs squeeze up to 12% before they scroll. The console's font is wider than Azahar's, so leave room.
- Tabs never take the D-pad ring; every tab shows its key (B on the left; set `actionKey`/`actionKeys` for the right tab).
- L and R jobs are named in the top screen's bottom corners with `ui::drawShoulderKeys`, not on the bottom screen; since the top screen takes no touch, the bottom screen keeps another way to the same action (Files: Options).
- Slow work goes through `tasks::busy`. Pass `cancellable` when stopping is safe (reads, network) and fill `Busy::done`/`total` when there is a count.
- Never call `C2D_DrawImageAt` in screens (use `ui::drawImage`) and never query AM every frame.
- Files keeps folder listings, folder totals and file dates in `fileIndex_` (`source/core/file_index`), saved to `sdmc:/3ds/3dsDL/index.bin` between runs. What loads is a first answer only: totals come back unverified and are added up again, listings are read again, and a date counts only while its file keeps its size. Bump `Version` in `file_index.cpp` when the saved form changes. Code in 3dsDL that writes, moves or removes something on the SD card calls `App::sdChanged(path)` afterwards. Writers outside Files are caught by `checkSdIndex` (free space moved), but a rename or same-size write is only caught by `sdChanged`.
- 3dsDL replaces itself (an older or the same version) only through `App::replaceRunning`: the CIA goes in uncommitted (`installer::installCia(..., commit=false)`), then the running title is removed and the import committed, then it restarts. Anything else would leave the console without 3dsDL if the install failed.
- Tickets are saved to `tickets/deleted/` before they are deleted. One the console will not export (homebrew CIAs' tickets, `0xE0E0803C`) is only deleted after `App::confirmUnsavedTickets` shows what it was and the person says Delete Anyway. Names of software seen installed are kept in `names.txt` (`titles::Names`), so what is left behind can be named.
- Files' favourites are `favorite=` lines in `settings.ini` (`source/core/favorites`), matched ignoring case. R stars, L lists them. Files' rename, cut and paste, and delete carry them along with `favorites::moved` and `removed`; anything else that moves or deletes an entry leaves its favourite Missing until it is removed.

## Archives

- `source/core/archives` reads and extracts: ZIP through 3dsDL's own reader (`zip.cpp`, stored and deflated, in stored order), everything else (7z, RAR, tar and compressed tars, ZIPs packed with bzip2, LZMA, XZ or Zstandard) through libarchive. Both write through `archives::Writer`.
- On FAT every lookup reads through the whole folder, so per-file calls are what makes thousands of files slow. Writer looks up nothing for a small new file: existing names come from one listing per folder (`FolderNames`), each folder is made once, and the file is just open, a size check on the open file, write and close. Only large files and files being replaced are looked up. Keep it that way.

## Receive

- Any web page can call `/send` with `folder=`, `replace=` and `extract=`, so the rules are in `source/core/remote` (`sendOptions`, `sentFileAllowed`, `sameApp`, `sentExtraction`) with host tests, and the console asks before each step. A sender never overwrites anything: a download keeps both on a clash, a replace needs `remote::sameApp` and a yes, and a sent archive only adds to a folder of the same app (`App::sentFolderHoldsSameApp`), with an app it updates put beside the old one for `App::replaceSent` to ask about. Keep new sender options to those terms.
- The page (`source/core/remote_page.cpp`) is a Finder-style browser: its sidebar's folders and Files' favourites come from `FileSharing::places` and `favorites` (`/api/places`), and Move To, Copy To, drags and paste go one entry per request through `/api/move` and `/api/copy` with `clash=keep` or `replace`, where Replace merges a folder into one of the same name (`fileops::merge`). Without `clash` a taken name is refused, as rename needs; a name that changes only in case is the entry itself, and `fileops::move` renames it through a spare name. Its editor comes from `/editor.js` (`FileSharing::editorScript`, gzipped, revalidated by an ETag), loaded the first time a file opens, and the plain text box stays for when it does not load.
- Files opened from Receive's list runs while the page can still change the card: `App::takePageChanges_` hands it what changed, and it reads its folder again through `ui::ListSpec::close` once the rows rest.
- Before asking, Receive follows each link's redirects with `net::whereTo` and names the host it reached; `QueuedLink::host` holds the download to that site (`url::site`), and one that lands elsewhere is a plain link. Every check and download from Receive refuses the console's own address, and another site's also this network (`remote::addressRefused`, through `CURLOPT_PREREQFUNCTION`, so redirects too). Sends not from 3dsDL's own page (`remote::fromOwnPage`: the console's address and the page's header) start on Cancel, `/send` takes at most `remote::MaxSentLinks`, and Don't Allow (offered once a device's links were cancelled) puts it on a links list of its own (`FileSharing::refuseLinks`), separate from the file page's. A sender's link downloads into the Download Folder and moves into its folder only once it belongs there.

## Testing in Azahar

- Azahar only takes taps while it has focus. A build with `THREEDSDL_EXTRA_DEFINES=-DTHREEDSDL_SCRIPTED_INPUT` also reads lines appended to `sdmc:/3ds/3dsDL/input.txt` (`tap X Y` in bottom-screen pixels, or `key A`, `key DOWN` and so on), so it can be driven in the background while screenshots come from the window.
- Azahar runs file Read, Write, SetSize and Close asynchronously, about a frame each, so time there follows the number of calls, not the bytes.

## Logs and crash reports

- `sdmc:/3ds/3dsDL/log.txt` (`source/app/logging`; line format and tests in `source/core/event_log`) records each session: console, memory, screens by name, error dialogs, and every download, install, extraction, file job, busy task, Titles read and update check with its numbers. It moves to `log.old.txt` at 256 KB. Report Issue shows the folder, and the bug form asks for it.
- Log a job once when it ends (`area.done`, `.stopped`, `.failed`), never per file or per frame. Fields are facts: counts, bytes, `ms`, result codes. Log hosts and file names, never whole URLs. `logging::trace` keeps a step in memory only, for crash.txt; use it for steps that matter when something breaks, like each title Titles reads.
- A crash on any thread writes `sdmc:/3ds/3dsDL/crash.txt` (`source/app/crash.cpp`; format and tests in `source/core/crash_log`) with the thread's name and the last 20 log lines, adds a line to log.txt, then the system's error screen shows as before. The kernel sends a worker's exception to the main thread's handler; `abort()` is wrapped at link time. Name a new thread with `tasks::startWorker`'s name, or a `crash::ThreadName` first in its entry function.
- Releases carry `3dsDL.elf`, and `scripts/build.sh` leaves it in `dist/`. `python3 -I scripts/crash.py crash.txt` names the functions and lines; a Luma3DS dump works too, with `--version`.
- A test build with `-DTHREEDSDL_FAULTS` aborts the Titles read when `sdmc:/3ds/3dsDL/faults.txt` has a `titles-abort` line.

## Hardware pitfalls

- A closed lid ends Wi-Fi twice over: sleep turns it off, and even with sleep refused NDM drops the connection for StreetPass unless its infrastructure state is held and locked. Work that has to outlast a closed lid holds an `awake::Hold` (`source/app/awake`), which does both, darkens the screens while the lid is shut and keeps the console up for 30 s after the last hold; `tasks::download`, `extract`, `install` and `fileOperation` already hold one. Never call `aptSetSleepAllowed` directly.
- Using a new libctru service or hardware block needs `resources/3dsDL.rsf` updated in the same change. Azahar does not enforce the RSF, so a missing entry only crashes the CIA on a console.
- Azahar has no real system font, so text widths there are not the console's.
- The console clock holds local time and mbedTLS reads it as UTC. Every curl handle that verifies certificates calls `net::useLocalClock`, so a certificate counts as valid when it is valid in some time zone.
- All of the process's socket calls share one network service session, served one request at a time, so a thread waiting inside the service stalls every other thread. The console links `poll()` through `net::pollInSteps` (`-Wl,--wrap=poll`), so it never waits there; keep sockets non-blocking and wait with `poll()`, never in a blocking `recv`, `accept` or `connect`.
